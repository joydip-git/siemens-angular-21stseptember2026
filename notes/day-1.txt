decorator (function) -> @decorator-name({})

@Component({}) => Decorator that marks a class as an Angular component and provides configuration metadata that determines how the component should be processed, instantiated, and used at runtime.

every component is accessed/used like a custom HTML tag. the selector of the component is where you decide/pass the name of that "tag"

in angular app, there might be hundreds of components. out of all, at least one component should be rendered in the body of the HTML, by default. that component is known "root" component (default)

in an app, created by angular cli, the name of the "root" component is - "app"
	- app.css [style]
	- app.html [template]
	- app.ts [code]
	- app.spec.ts [unit test case file]

this component has selector value "app-root" (the tag name for the component)
note: every component's tag name should start with a prefix (such as "app"), followed by the name of the component, so that the custom tag does not conflict with the built-in HTML tags

for example: 
	component class name PersonList
	selector-value: app-person-list
	or app-person-data

this root component is rendered in index.html file's <body> element where <app-root> tag is used


bootstrapApplication => Bootstraps an instance of an Angular application (of type ApplicationRef) and renders a standalone component as the application's root component

ApplicationRef => A reference to an Angular application running on a page.

Angular Features:
------------------------
Binding:
	how to pass data from code to template: 
	data binding - binding data from the code of a component to the element(s) in the template of the same component
	syntax:
	a. {{ prop-name }} -> interpolation or mustache syntax
	b. <element [attribute]="prop-name"> -> property/attribute binding
	
	how to pass data from template to code:
	event binding -> bind an event in the template of a component, with a method from the code of the same component
	syntax: <element (event)="method(arguments)">


directives:
----------------
NgFor => *ngFor

@Directive({
	selector:'[ngFor]'
})
export class NgFor{
	method(expression, template){
		return ....
	}
}

1. structural: manipulate DOM
 ex: ngIf, ngFor, ngSwitch

starts with *
used like an attribute

2. attribute directives: extend the behavior of the existing element
ex: ngClass, ngStyle, formGroup, formControl etc.
start with no special character
used like an attribute

3. component directive: a component is a directive too, but the one with template. no other directive has template.
start with @Component({})
used like a custom HTML tag
