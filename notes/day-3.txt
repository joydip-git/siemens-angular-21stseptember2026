HTTP requests:
-------------------
built-in service class: HttpClient
provider function: provideHttpClient(): Configures Angular's HttpClient service to be available for injection.

nowadays in Angular HttpClient provider is provided by default at the root. 
You don't have to call this method, until and unless, you have to "enhance" the HttpClient

HttpClient: 
	methods -> get(), post(), put(), patch(), delete(), options() etc.

asynchronous -> they send the request but do not block the single thread of JS
API for response -> Observable
		this object is returned by each of the HttpClient method whenever you call those methods
		observable object is an API provided by 3rd party: RxJS 
		observable object is used to store the incoming response fron the backend
		anyone who wants to extract/receive/consume that data from observable, has to subscribe the observable

effect: Registers an "effect" that will be scheduled & executed whenever the signals that it reads changes.

lifecycle:
----------------------
created and destroyed

mounting:
--------------
field initialization
constructor executed
changes event gets fired 
	if the component has input decorated property, the component receives the first value from the parent component via that property just after constructor execution
this is the time when "changes" event gets fired
you can handle this event with a particular method: 	ngOnChanges(changes:SimpleChanges) => void
	[implement OnChanges interface]

this event gets fired every time nested component receives fresh data via the input decorated property from its parent (including the first time)

init event gets fired
	immediately after changes event, another event gets fired, "init"
	you can handle this event with a particular method: ngOnInit() => void
	[implement OnInit interface]
	this event gets fired ONLY ONCE in the lifecycle of the component


update:
------------
changes event gets fired if nested component receives fresh data via the input decorated property from its parent

destroy:
------------
an event gets fired just before the component gets destroyed "destroy"
	you can handle this event with a particular method: ngOnDestroy() => void
	[implement OnDestroy interface]
	this event gets fired ONLY ONCE in the lifecycle of the component
